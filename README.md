# Sultan Sofrası · Türk Restoranı · Digital Menu

Live: **https://sultansofrasi.vercel.app** · Admin: **/admin** · QR codes: **/qr**

A mobile first digital menu for a Turkish restaurant. Everything (UI, dishes, categories, slogans, admin) is in Turkish, prices in Turkish lira (₺). Every dish shows calories and allergen badges (14 EU allergens), plus signature, spicy and vegetarian tags. No build step: static HTML/CSS/JS plus three Vercel Functions.

## Structure

| Path | Purpose |
| --- | --- |
| `index.html`, `assets/js/app.js`, `assets/css/style.css` | Public menu: category tabs with scrollspy, search, allergen/vegetarian/kcal filters, live "open now" status (Europe/Istanbul), allergen legend, contact, meal cards |
| `admin.html`, `assets/js/admin.js`, `assets/css/admin.css` | Password protected dashboard: dishes, categories, images (logo, banner, gallery, optional per dish photo), restaurant info, hours, JSON backup/restore |
| `assets/js/icons.js` | Hand drawn SVG allergen and UI icons shared by both pages |
| `api/menu.js` | `GET` menu JSON, `POST` save (auth) |
| `api/upload.js` | `POST` image upload, `DELETE` image (auth) |
| `api/login.js` | `POST` password check |
| `data/default-menu.json` | Seed menu, used until the first save |
| `assets/qr/` | Two branded QR codes (PNG for print, SVG for scaling) |
| `scripts/make-qr.mjs`, `scripts/verify-qr.py` | Regenerate and decode check the QR codes |

## Storage and auth

* Data and images are stored in **Vercel Blob** (store `sultan-menu-blob`, connected to the project, which provides `BLOB_READ_WRITE_TOKEN`). Each save writes a new JSON object and keeps the last 5 versions, so CDN caching never serves a stale menu.
* If no Blob token exists, the public menu falls back to `data/default-menu.json`, and the admin keeps unsaved edits as a draft in the browser's localStorage but cannot publish them.
* The admin password comes from the `ADMIN_PASSWORD` environment variable (set in Vercel project settings). It is sent as a header over HTTPS and compared with a constant time check. There is no rate limiting or multi user account system; change the password in Vercel and redeploy if it leaks.
* Images are resized in the browser (max 1600 to 2000 px, WebP) before upload because Vercel Functions accept request bodies up to 4.5 MB.

## Local development

```bash
npm install
ADMIN_PASSWORD=dev npm run dev     # http://localhost:3000, storage emulated in .local-blob/
```

## QR codes

```bash
node scripts/make-qr.mjs https://sultansofrasi.vercel.app
pip install zxing-cpp pillow && python3 scripts/verify-qr.py
```

Both codes use error correction level H, so the centre emblem does not affect scanning. They were decoded successfully with ZXing at 100%, 50%, 25% and 15% size.

## QR table ordering (kitchen tablet)

Customers scan the table QR (`/?table=5`), order from the menu, and the order appears on the kitchen tablet (`/kitchen`) in real time. The customer sees the live status (new, preparing, ready, served).

| Path | Purpose |
| --- | --- |
| `assets/js/order.js`, `assets/css/order.css` | Cart, order submit, "Siparişlerim" live status (only active when a valid `?table=` is present) |
| `kitchen.html`, `assets/js/kitchen.js`, `assets/css/kitchen.css` | Kitchen tablet: PIN login, 4 status columns, repeating sound + flashing bar for new orders, wake lock |
| `api/order.js` | `POST` place order (validated against the server menu), `GET ?ids=` own order status |
| `api/orders.js` | Kitchen only (PIN): `GET` live list, `POST {id,status}` change status |
| `api/config.js` | Public client config (table count, Realtime URL + anon key) |
| `api/_orders.js` | Validation, rate limits, storage (Supabase, or a JSON file in local dev) |
| `supabase/schema.sql` | `orders` table, RLS enabled with no policies |
| `masa-qr.html`, `assets/qr/tables/` | Printable per-table QR codes, generated by `scripts/make-table-qr.mjs` |

**How it is real time:** the API writes to Supabase Postgres with the service role key, then sends a tiny Realtime broadcast "ping" (no order data). The kitchen and the customer's phone react to the ping by refetching through the API. Both also poll every 3 to 4 seconds, so ordering keeps working if the websocket is blocked.

**Environment variables (Vercel):**

| Name | Meaning |
| --- | --- |
| `SUPABASE_URL` | `https://<ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | server only, never exposed to the browser |
| `SUPABASE_ANON_KEY` | publishable key, used only for Realtime pings |
| `KITCHEN_PIN` | PIN for `/kitchen` (falls back to `ADMIN_PASSWORD`) |
| `TABLE_COUNT` | number of tables, default 30 |

**Abuse protection:** orders are rebuilt on the server from the live menu (client prices ignored), table must be 1..`TABLE_COUNT`, qty 1..20, max 25 lines and 60 items, note max 200 chars, 4 orders per IP per 2 minutes, 6 open orders per table, honeypot field, same-origin check, 8 wrong kitchen PINs locks the IP for 5 minutes (per serverless instance). Limits live in `api/_orders.js`.

**Local test (no Supabase needed):** `ADMIN_PASSWORD=dev npm run dev`, open `http://localhost:3000/?table=5` and `http://localhost:3000/kitchen` (PIN `dev`). Orders are stored in `.local-blob/orders.json`.

```bash
node scripts/make-table-qr.mjs https://sultansofrasi.vercel.app 30   # regenerate
python3 scripts/verify-table-qr.py https://sultansofrasi.vercel.app 30
```
